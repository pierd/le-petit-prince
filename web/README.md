# Le Petit Prince — interactive reader

A static web app for reading *Le Petit Prince* in French with a literal
Spanish translation alongside, built with Vite, React and TypeScript and
deployed to <https://pierd.github.io/le-petit-prince/>.

## Features

- **One chapter at a time**, French by default. A collapsible table of
  contents on the left (an overlay on phones); ‹ › in the top bar and the
  ←/→ keys change chapter.
- **Spanish on demand.** The "Español" toggle (or `S`) adds the Spanish next
  to the French, paragraph by paragraph; on phones it goes under each French
  paragraph.
- **Word alignment.** Hovering a word highlights it and its counterpart in
  the other language, as a phrase (`J'ai … vécu` ↔ `viví`). With the Spanish
  hidden, the translation appears as a tooltip instead.
- **Word popup.** Clicking a French word shows its dictionary form, what form
  it is in (tense, mood, person; gender and number; contraction or elision),
  its translation in this sentence and its usual translations in the book,
  and for verbs the full conjugation, opened on the mood of the form, with
  the form highlighted, compound tenses and pronominal verbs included.
  Clicking a Spanish word shows its type and the French it translates.
- **Audiobook.** A player bar with play/pause, previous/next paragraph, a seek
  bar, speed and "Suivre" (scroll along). The paragraph being read is marked
  and the word being read underlined; "▶ Écouter d'ici" in the popup plays
  from that word. Playback continues into the next chapter, and the chapter
  shows on the lock screen and in headphone controls (Media Session).
- **Mobile.** The popup becomes a bottom sheet (swipe down to close) and
  scrolls the tapped word above itself; hover-only behaviour is limited to
  devices that can hover.
- **Installable and offline.** It is a PWA. The app shell is cached
  automatically and chapters are kept as they are read; downloading the
  whole book (text, illustrations, audio, about 43 MB) is the reader's
  choice, from "Hors ligne" in the table of contents.

## Running

```sh
npm install
npm run dev       # http://localhost:5173/le-petit-prince/
npm run build     # type-check, then build into dist/
npm run preview   # serve dist/ (the service worker only runs in a build)
```

`npm run dev` and `npm run build` first run `prepare-public`, which copies
`../images` into `public/images/` and writes `public/offline.json`; both are
generated and ignored by git.

The site is served from `/le-petit-prince/`. Set `BASE_PATH` to build for
another path (the deploy workflow sets it to `/<repository name>/`).

The data in `public/data/` and `public/audio/` is generated by
`../tools/annotate.py` and `../tools/audio.py` (see the root README) and
committed; the app never computes grammar or alignment itself.

## Data

All under `public/data/`, written by the tools in `../tools/`; the types are
in `src/types.ts`.

- **`toc.json`**: chapters in order, with their French and Spanish titles.
  Ids are the source's keys: `ppded` (the dedication), `ppchap1` …
  `ppchap27`.
- **`chapters/<id>.json`**: the chapter's blocks, paragraphs and images. A
  paragraph has `fr` and `es` token lists. A token is
  `{ t: text, s: trailing whitespace }`, plus, for words: `l` lemma, `p`
  part of speech (Universal POS), `f` morphological features. French words
  also have:
  - `a`: indices of the Spanish tokens they are aligned with
  - `v`: verb readings, best first, as `"mood:tense:person-number"`
    (verbecc's names, e.g. `indicatif:passé-simple:1s`)
  - `r`: the verb is used pronominally
  - `c`: the compound tense (`passé composé` …) the word is part of, with the
    token indices of the auxiliary and the participle
- **`verbs.json`**: for every verb in the book: the auxiliary, the
  participles, and the simple tenses (six forms each, three for the
  imperative). `conjugate.ts` builds the compound tenses from these and the
  forms of avoir and être.
- **`lexicon.json`**: `"lemma|POS"` → the Spanish lemmas it is most often
  aligned with across the book, with counts (the popup's "Usually").
- **`audio.json`**: per chapter, the audio file (with a `?v=` content hash),
  its duration, and the start time of each French word, as
  `[token index, seconds]` per paragraph key. The dedication is not narrated
  and has no entry.

`public/audio/<id>.m4a` holds the chapter audio (AAC, mono, 48 kb/s).
`public/offline.json` lists every file the offline download fetches, with
sizes.

## How it works

**Alignment.** Links are stored on the French side only (`a`). Hovering
highlights the word plus everything one hop away: its Spanish tokens and the
other French tokens linked to them. This gives phrases like `il … était` ↔
`era` without storing groups. Group ids were tried first, but transitive
grouping chained alignment errors across whole sentences.

**Grammar notes.** `describe.ts` picks, in order: the verb reading (with a
note on the tense's use, and on the compound tense when the word is an
auxiliary or a participle), the hand-written function-word note (looked up as
`form|POS`, then `form`, so *des* or *du* get the right explanation as an
article or a contraction), and otherwise part of speech, gender and number.
Explanations are in English, translations in Spanish, French grammatical
terms kept.

**Conjugation.** `verbs.json` has only simple tenses. Compound tenses are
built as auxiliary + participle, with être and agreement for être-verbs and
pronominal ones. Pronominal tables get reflexive pronouns with elision
(*je me prépare*, *je m'endors*). verbecc's own compound forms are not used:
verbecc does not know pronominal verbs take être.

**Audio.** One `<audio>` element follows the open chapter. The word being
read comes from a binary search over the chapter's word times. It is read in
a `requestAnimationFrame` loop while playing, and state only changes when the
word changes, because `timeupdate` (4 Hz) is too coarse for words. When a
chapter ends, `usePlayer` asks `App` to open the next one and marks the next
load to autoplay.

**Offline.** `sw.ts` precaches only the app shell. Data, images and audio
share one cache, `lpp-offline-v1` (`src/offlineCache.ts`):
- data is stale-while-revalidate, so saved text refreshes when online
- images are cache-first
- audio is answered from the cache when saved, otherwise passed through to
  the network uncached

The audio element asks for byte ranges. A saved file is answered with a 206
response built by `workbox-range-requests`, without which Safari won't play
cached audio.

On iOS, though, `<audio>` loads through the system media stack, which skips
the service worker. So `usePlayer` doesn't rely on it: when a chapter's
audio is saved, the player reads it from the cache itself
(`savedBlob()` in `offline.ts`) and plays it from a `blob:` URL. It switches
to the saved copy:
- when a chapter opens
- when a download finishes (the `lpp:offline-saved` event)
- when the connection drops
- when a network load fails The download is opt-in because it is 43 MB. It asks for
persistent storage, and on completion drops cached audio whose `?v=` hash is
no longer listed. On iOS a home-screen app has storage separate from Safari,
so the download has to happen in the installed app.

**Layout.** The popup is a bottom sheet below 600 px (`SHEET_QUERY` in
`WordPopup.tsx`, matched in `styles.css`); the table of contents is an
overlay below 900 px. Colours are CSS variables with a dark theme under
`prefers-color-scheme`. Settings (Spanish on, sidebar, speed, follow) are
remembered in `localStorage`.

## Deploying

Pushing to `main` runs `.github/workflows/pages.yml`, which runs
`npm ci && npm run build` here and publishes `dist/` to GitHub Pages.
